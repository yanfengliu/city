# 2026-08-18 — Adversarial review of D2 (school runs)

## What was believed, and proved false

**Believed:** D2's slot↔walker invariant held, because a contract test asserted it over a full simulated day.
**False:** that test never touched a workplace. `unassignWorkers` (fired by bulldoze *and* by ordinary abandonment) destroyed every `pedestrianPath` the citizen owned with a raw `destroyEntity` — correct in the one-agent-per-citizen era, wrong the moment D2 added a second walker class whose lifecycle is slot-coupled. Nothing dropped the slot: the due-loop only services `atPlace`, and the departure scan skips any member that already has one. The child never attended school again for the life of the household, and the zombie slot serialized into every later save. Deterministic, so the replay gate stayed green while the state was wrong.

**Believed:** "covered" and "attends" agreed, because `schoolFor`'s docstring said it used the `nearestVenues` ranking.
**False:** it shared the *ranking* but not the *metric* or the *reachability filter*. `SERVICE_RADIUS` is documented as Chebyshev from the anchor cell — what `markCoverage` paints and what growth's `educated` reads — while `schoolFor` gated on access-cell Manhattan ≤ 32. A home 22 east and 22 north is covered at Chebyshev 22 and rejected at Manhattan 44. Separately, `nearestVenues` filters to the home's road component and `schoolFor` did not, so a school across an unbridged river permanently shadowed a reachable one.

**Believed:** the `school` purpose had its own wardrobe palette, as PROGRESS.md and the devlog both stated.
**False:** `PEDESTRIAN_PURPOSE_TOP_PALETTES.school` had no consumer at all. The mesh styles by identity from `PEDESTRIAN_TOP_COLORS`, which spreads only commercial/industrial/shopping; `purpose` never reached `pedestrianStyle`. The entry existed only because the `Record<PedestrianPurpose, …>` type demanded one. A feature claimed in our own documentation did not exist.

## What a reviewer caught that the author missed

All seven findings came from the review, not from the suite — 745 tests were green when it started. Both lenses independently ranked the same two defects first, and lens 1 proved both by writing throwaway probes.

The subtle one was `activeAgent`: it returns the first `pedestrianPath` by entity id and checks pedestrians *before* vehicles. D2 broke that one-agent premise, and because the member pass runs first each tick the child's walker usually holds the LOWER id. So the household row tracked the child: a driving commuter was reported "home", the Places section printed the school as a work destination, and the map position was the child's. The existing whereabouts test passed anyway because it only checked vocabulary membership.

Raising `MAX_PEDESTRIANS` would relieve the afternoon figure, but that is a rendering and performance budget.

## The trap worth carrying forward

Finding 3's first contract test **passed with the fix deliberately disabled**. Driving the trip system, an unreachable school choice produces no walker — indistinguishable from "the departure moment has not arrived yet" — so the assertion sat inside a branch that never ran. Rewritten to assert `schoolFor` directly, it fails with the filter off (picks 46, wants 32).

Three more instrument faults in the same session, each caught only by reading the failure text instead of the exit code: `sim.world.getPosition` does not exist; `citizenDetail` takes `(sim, entity)`, not `(sim, world, entity)`; and one assertion compared a `place` object against a raw entity id. A fourth was subtler — the first version of the "same person twice" fixture never reproduced the collision at all, and only a deliberate seed sweep across a wider street found it at seed 11.

Working rule, now lesson 28: when a defect's signature is ABSENCE — no agent, no event, no row — never assert it through the system that would have produced the thing. Assert the deciding function, and guard the fixture so it fails loudly if it stops exercising the case. Confirm RED for the intended reason before writing the fix; after fixing, re-break the fix and watch the test fail.

## Browser verification

The school wardrobe is a visual claim, so it was verified visually rather than by test alone. The Browser pane would not composite in this session (screenshots timed out with the page alive and eval working), so a Playwright driver built a served town, stopped on a morning with school walkers out, selected an instance whose RENDERED top color matched the school palette, and photographed it: two children on the sidewalk in bright red (#d85050) and bright green (#67b35c), plainly distinct from the muted commercial blues beside them. The full-frame sweep found nothing else wrong — terrain, lake, signals with lit lenses, lane markings, sidewalks, buildings, advisor, and HUD all read correctly.
